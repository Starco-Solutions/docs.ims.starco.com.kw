Autos and Shopify provisioning

Administrator procedure for IMS Autos 9.2, Shopify Integration Server 4.4.0, IMS Global 1.7.0 and IMS API 1.1.0. Register service identities, authorize companies, prepare the published binaries and use the one-time recovery installer without transferring raw service credentials.

Scope and authorityUse this guide only on an expressly approved administration host and database. The company schema and required role grants must already exist. Provisioning a service identity does not create a company database, migrate old data, create a Shopify Store App Token, activate Autos schedules or start Shopify workers. Keep real connection strings, tokens, company IDs and host details in approved private operational records—not public documentation.

Although the registration utility is named IMS.AutosProvisioner, the identity registry is shared. A first grant in IMS Global assigns the selected identity to Autos or Shopify. Do not use the utility's Autos-only grant-company operation to grant a Shopify identity; Shopify grants use shopify_service.company_access, while Autos grants use autos_service.company_access.

1. Prepare the approved administration environment

  1. Confirm the current authorized IMS Global and IMS API versions, approved company registry and production schema migrations. New-company database roles and API contracts are provisioned by Global's company-creation procedure; service identities and per-company grants are separate.
  2. Use the Release build of the console utility from IMS_API/tools/IMS.AutosProvisioner. Administrators may keep a restricted copy in a separate Provisioning tools folder alongside the IMS Global administration distribution. This is an operational file arrangement, not a claim that Global itself compiles or installs the utility.
  3. Use a privileged PowerShell session on the authorized administration host; do not copy its provisioning environment to the Autos/Shopify service host. Configure IMS_AUTOS_PROVISIONING_GLOBAL for the exact approved Global database and transport mode. The utility defaults to VerifyFull if SSL Mode is omitted. Disable is supported only when approved for that database. Never bypass certificate validation.
# Execute in an approved administrative PowerShell session.
# Enter credentials interactively; do not paste a database password into history.
$pg = Get-Credential -Message "Approved Global PostgreSQL administrator"
$builder = [System.Data.Common.DbConnectionStringBuilder]::new()
$builder["Host"] = "APPROVED-PRIVATE-DB-HOST"
$builder["Database"] = "ims_global"
$builder["Username"] = $pg.UserName
$builder["Password"] = $pg.GetNetworkCredential().Password
$builder["SSL Mode"] = "Disable"  # Only where this DB transport mode is approved.
$env:IMS_AUTOS_PROVISIONING_GLOBAL = $builder.ConnectionString
Remove-Variable builder, pg
# Remove the environment variable when provisioning is complete:
# Remove-Item Env:IMS_AUTOS_PROVISIONING_GLOBAL

Verify the intended host/database and role without printing the connection string or password. The utility reports completion without displaying credential values. End the session or remove the environment variable after all approved commands.

2. Register Autos and Shopify identities

Run create-service once for each new identity, keeping the generated IDs in the approved private administration record. Choose clearly distinguishable display names for each environment. Do not paste a previously issued bearer credential into a terminal argument, ticket or application setting.

# Run the Release build from an authorized administrator machine.
# Use the provisioner supplied with the IMS API administration tools.
$autosId = [guid]::NewGuid().ToString()
$shopifyId = [guid]::NewGuid().ToString()
& ".\IMS.AutosProvisioner.exe" create-service $autosId "IMS Autos ENV"
& ".\IMS.AutosProvisioner.exe" create-service $shopifyId "IMS Shopify ENV"
# Store the two IDs in the approved administrative record.
# Grant both identities to their respective service in IMS Global, not by
# calling the Autos-only grant-company command for the Shopify identity.

The utility also supports issue, revoke-credential, disable-service, disable-company, and vault/workload commands for specifically approved administrative procedures. The normal recovery installer obtains new protected credentials through single-use API enrollment; do not manually issue or distribute service credentials merely to run that installer. grant-company is an Autos-specific grant path and is not the standard route for assigning Shopify.

3. Grant access from IMS Global

  1. Open IMS Global → Services → Service Administration and select the approved company.
  2. Select IMS Autos, choose the new Autos identity, then Grant Company Access. Verify Service access: GRANTED.
  3. Switch Service to IMS Shopify, choose the separate Shopify identity, and grant company access. Confirm its independent GRANTED status.
  4. Leave Autos: DISABLED until installation, company schedules and connected destinations have been checked. Shopify does not use this switch; its company/profile worker must be explicitly started in the desktop application.

For a newly created company, repeat the relevant company grants and configure Autos job settings, Shopify Profile and Store mapping, and any approved workload references. The existence of a Global company record alone does not grant either worker access.

4. Prepare the recovery packages

IMS Global's Generate Recovery Package reads two published ZIP files from its Packages directory and unchanged installer/importer assets from RecoveryAssets. The published ZIPs must contain the named net10.0-windows folder, not application files directly at ZIP root:

Packages/
  IMS-Autos-9.2.zip
    net10.0-windows/
      IMSAutos.exe
      IMSAutos.runtimeconfig.json
      appsettings.json
      ... other published files ...
  IMS-Shopify-4.4.zip
    net10.0-windows/
      ShopifyIMS.exe
      ShopifyIMS.runtimeconfig.json
      shopify-service.json
      ... other published files ...

RecoveryAssets/
  Import-AutosServiceCredential.ps1
  Import-ShopifyServiceCredential.ps1
  Install-AutosCredential-System.ps1
  Install-IMS-Services.ps1
  Install-IMS-Services.cmd

Verify that the contents are the approved current published builds and that the architecture/runtime files accompany each executable. Do not package obsolete application binaries from another build or include generated browser-cache folders. Global checks ZIP structure, required executable/settings and approved importer integrity before issuing a recovery ticket. IExpress is used to generate the single-file installer on the Global administration machine.

5. Generate and execute one recovery installer

  1. Prepare a replacement Windows machine with .NET 10 Windows Desktop Runtime x64 and Windows PowerShell. Confirm the machine can reach the API over HTTPS and the authorized company database endpoints. Network TLS to the API and PostgreSQL database SSL are separate configuration layers.
  2. Preserve the required nonsecret Autos CredentialsByCompany references and Shopify config.ini preferences. Drain active work and isolate the old Autos/Shopify host before installation; never run both hosts with the same business workload active.
  3. In Global, select Generate Recovery Package. Confirm the displayed Autos and Shopify identities and approved API HTTPS origin. The generated executable contains a single-use 30-minute enrollment ticket, not a stored service bearer token or database password. Keep the executable private.
  4. Sign in on the target machine as the intended Shopify desktop user and run the generated IMS-Services-Recovery-…exe, elevating under that same Windows account. Running as a different administrator would protect Shopify's DPAPI credential for the wrong account. Do not run as SYSTEM.
  5. The installer checks package hashes and runtime, stages both applications, redeems the ticket, installs Autos credential protection for LocalSystem, provisions Shopify's protected credential for the signed-in user, configures and starts the IMS Autos service, and creates a Shopify shortcut.
  6. Open Shopify from its shortcut and verify the intended company/profile and Store mappings. Shopify is a desktop application and does not start synchronized workers just because its shortcut was created. Enable each intended profile's automatic Start/Run on startup choices only after checking the configuration; this preference is not a Windows startup registration.

If the ticket expires or was redeemed, generate a new recovery package; do not rerun the old ticket as a recovery strategy. New enrolled bearer credentials have a 30-day lifetime and shorter authorization leases; arrange renewal before expiry. The recovery installer does not automatically revoke old-host credentials, so retire them only after the replacement is verified and the old host is isolated.

The documented IMS 9 delivery uses Disable for PostgreSQL and HTTPS for the API. A deployment using VerifyFull must configure database certificate trust and an absolute valid root-certificate path where required; neither worker silently downgrades certificate checks.

7. New companies, credential retirement and incident handling

A new company requires the Global-created database, intended company role grants, registration in the Global company registry, specific Autos/Shopify company grants, and independently configured business controls. Autos company enabling controls only Autos scheduling. Shopify company authorization does not itself create a profile, map a Store or add App Tokens. Reopen/restart Shopify to discover a newly authorized company.

Stop the Shopify profile through Stop and allow in-flight work to finish before changing it. An API authorization expiry prevents admission of new work but does not forcibly retract an already admitted operation. For Autos, disabling the company stops future scheduling while the current company cycle completes.

On an installation error, capture the installer phase and safe service-state diagnostics; do not disclose tokens, database passwords or private payloads in logs or screenshots. Review the installed files, service state and authorizations before issuing another ticket. Keep prior credentials available for controlled rollback until the new host has passed its acceptance checks.
