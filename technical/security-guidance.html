General Security Recommendations

Practical security precautions for teams operating IMS environments. These are recommendations, not statements that IMS implements every measure or that an exposure has been discovered.

How to read this guidanceRecommendations describe actions administrators and developers should consider. They are not findings, confirmed incidents or IMS product guarantees. For implemented controls and documented boundaries, see Security Architecture, Secure Bootstrap and Secret Vault.

Types of security statements

LabelMeaning
Documented IMS behaviorAn IMS control or interface described by the technical reference. Implementation verification is still required before treating documentation alone as source-code proof.
General recommendationA precaution or deployment practice to consider. Its inclusion does not imply IMS provides it automatically, that it is missing, or that a defect exists.
Confirmed limitationA specific limitation established through evidence and scoped to the relevant component/version. Hypothetical threats or common technology trade-offs are not confirmed defects.

Workstations and runtime processes

  • Keep supported workstation and server operating systems patched; retire or isolate unsupported systems according to an approved risk plan.
  • Restrict local administrator rights and access to running processes, memory dumps, remote administration and diagnostic tools.
  • Apply screen locks, endpoint protection and device encryption as appropriate for the deployment.
  • Keep runtime credentials and tokens out of unattended screenshots, crash reports, support attachments and shared folders.

Secrets, keys and credentials

  • Grant credential and encryption-key access only to approved operators and service identities; review access periodically.
  • Use supported IMS administration and vault workflows for credential changes. Coordinate rotation with consumers and verify connectivity afterward.
  • Protect backup copies of encrypted secrets and the key material required for recovery; store recoverable copies under separate, controlled access.
  • Never include live passwords, tokens, API keys or encryption keys in documentation, sample requests, tickets or scripts.

Logging, diagnostics and support sharing

  • Redact passwords, database connection secrets, tokens, authorization headers and sensitive personal data before retaining or sharing traces.
  • Restrict log access, use appropriate retention limits and review logging settings after troubleshooting.
  • Prefer masked example values and verify attachments before sending them to external providers.
Memory exposure is not a logging findingWhere an authorized component receives decrypted runtime credentials, plaintext may exist in its process memory while in use. This does not establish that credentials are stored permanently or written to logs. Either claim requires separate implementation evidence or testing.

Network and access boundaries

  • Limit PostgreSQL, API and administrative network access to the systems and operators that need it; segment POS and server networks where practical.
  • Use approved encrypted transport, certificate validation and least-privilege database/service roles appropriate to the installation.
  • Review API key scopes, workstation permissions, company access and service grants regularly; remove stale access.

Backups, recovery and incidents

  • Protect backups, document key dependencies and practice controlled restoration of databases and required secrets.
  • Monitor authentication failures and unusual access using approved tools without treating alerts alone as proof of an incident.
  • If credential exposure is suspected, preserve evidence privately, contain access and rotate affected credentials through an authorized response procedure.
  • Never use unsupported direct database changes as a shortcut around IMS authorization or recovery workflows.

These precautions complement, but do not replace, the supported IT Operations & Troubleshooting procedures and PostgreSQL Deployment & Operations guidance.
