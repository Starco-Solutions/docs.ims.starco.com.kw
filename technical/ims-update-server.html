IMS Update Server

Configure authorized Client and IMS Global release sources through the supported IMS Server installer. Use the correct update-compatible application releases and verify downloads from approved workstations.

Who can receive an update

IMS provides update access only to workstations approved through IMS Global → System → Workstations. A pending or blocked device cannot receive an authorized update. Review the workstation roster before enabling or changing the service.

Keep updates authorizedDo not expose distribution folders as publicly downloadable directories. Validate the trusted software source and use normal workstation authorization and administrator-approved release procedures.

Prepare Client and Global releases

  1. Prepare the approved Client release files Update.exe and IMS_Update.zip in one accessible distribution folder.
  2. Prepare the approved full IMS Global distribution as Global_Update.zip in a separate distribution folder.
  3. Choose local folders or approved shared folders that the IMS API service can read. Verify network share and Windows access through the target service host, not just through an administrator's interactive session.
  4. Confirm the versions and files correspond to the approved release before continuing.

Configure IMS Update Server

  1. Open the approved Setup.exe package on the IMS API server and choose Configure IMS Update Server only (existing API installation) under Installation mode.
  2. Complete the displayed prerequisite checks. Supply the existing IMS API IIS site, trusted HTTPS hostname and port when requested.
  3. Review the currently configured release source and any displayed replacement warnings; confirm the intended setup before proceeding.
  4. Enter the Client and Global release source folders. If a folder is a UNC share, choose the supported access mode and provide any required read-only account information in the installer's protected prompts.
  5. Review the Global release version detected by Setup and correct the distribution if it differs from the approved version.
  6. Complete the installer's protected configuration prompts as directed. In a multi-node installation, configure every node consistently under the organization's approved administrator procedure.
  7. Confirm Apply this API-authorized IMS Update Server configuration? and wait for Setup to verify its operation.
  8. Test the intended Client and Global downloads from an approved workstation and verify the installed application versions.

Protect update administration

Source-folder access, approved release metadata and protected settings belong to the IMS Server administrator. Configure them through the installer, not by distributing local configuration files or credentials to workstations. Use General Security Recommendations for account and network precautions.

Single-server and two-node installations

For one IMS API server, configure the Client and Global distribution folders once. For two authorized load-balanced IMS API nodes, run the supported configuration workflow on each node and verify they serve the same approved release. Check source-folder permissions, certificate trust and update downloads through both nodes.

Change an existing configuration

Run the installer in Configure IMS Update Server only mode to change source paths, approved release files or share access. Review existing configuration and follow the installer's protected prompts. Avoid deleting or reinitializing the API, company databases or unrelated IIS sites for a source-folder change.

Existing Client and Global installations

Only update-capable application releases can use the authorized update service. Keep any approved existing Client update method available until affected workstations have compatible software. IMS Global installation remains an administrator-controlled distribution procedure; publishing new release files does not automatically replace an existing Global application.

Verify and troubleshoot

SymptomAdministrator check
Workstation cannot updateVerify the workstation is approved, the running application version is update-compatible, and the API HTTPS endpoint is reachable.
Release missing or outdatedReview the configured Client/Global source folder and its approved release contents.
Shared folder cannot be accessedReview UNC/share permissions for the IMS API service identity and retry the supported configuration mode.
Two nodes behave differentlyVerify both nodes use matching approved release content and the same authorized update configuration.
Installation interruptedKeep the reported Setup phase and follow its supported retry path. Do not replace unrelated server or database configuration.
