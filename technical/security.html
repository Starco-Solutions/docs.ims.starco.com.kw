Security Architecture

Layered IMS security covering workstation authorization, global authentication, Global Administrator access, company membership and company-local permissions.

Security layers

LayerControl
WorkstationIMS checks the registered workstation identity before authentication; authorized administrators can approve or block devices.
Global identityLogin credentials and account state are centralized and are not duplicated as independent passwords in each company database.
Global administrationIMS Global requires a valid Global Administrator session. Administrative modules revalidate that session before opening.
Company membershipOnly companies assigned to the global user are eligible for login/selection.
Company-local authorizationGroup Policies, Store/Supplier scope, transfer scope and operational privileges are maintained in the selected company.
SecretsVault-managed credentials are encrypted at rest. Authorized bootstrap/runtime flows can return decrypted credentials to the requesting component; protect client memory and logs accordingly.

Administrative self-protection

IMS Global prevents the account currently running the administration application from removing its own Global Administrator flag, disabling itself or resetting its own password from the Global Users screen. It also prevents the current workstation from blocking itself.

Authorization boundaries

The Business API uses API keys, client-company assignments and endpoint scopes. Bootstrap, Global administration and runtime-secret APIs use separate session contracts. A Business API key does not grant Global Administrator or runtime-secret access.

Runtime-secret checks include client version, session/workstation binding, active user, active company membership and authorized workstation. These checks do not establish fine-grained company Group Policy or menu-level enforcement in the API. Company-local permissions remain a separate layer.

Availability and session state

The inspected bootstrap and Global Administrator session stores are in-process. Multi-instance operation requires a verified routing/shared-state design; this source review does not establish deployed high availability.

Source verification: IMS.Api main 91759f4, reviewed 9 October 2026 (provisional source baseline; deployment/release equivalence not verified).
