Secret Vault

How IMS keeps sensitive database and integration credentials behind the server-side API boundary and exposes only the runtime values needed by authorized components.

Purpose

IMS uses a central protected secret store for credentials that should not be distributed as reusable plaintext application configuration. Access to those values is mediated by IMS.Api and tied to the requesting user/session, workstation, company/module/resource and intended secret.

Company database passwords

The IMS Global Companies screen can register/change a company database password, but an existing saved password is not displayed back in the form. During new database provisioning, IMS Global uses the password supplied for the new database and, after successful creation/validation, stores the secret through IMS.Api.

Operational rule

Do not bypass the vaultDocumentation and integrations should use the approved IMS secret flow rather than copying database/service passwords into user guides, scripts or workstation configuration.

Encryption and authorized runtime access

Vault-managed credentials use authenticated AES-GCM encryption at rest. Access is mediated by IMS.Api and restricted to the authorized identity, company and purpose. Authorized components can receive the credentials needed for their runtime work; protect those processes, their memory and their logs.

Status checks report whether a secret is configured without displaying its value. Secret reads and updates are audited. A stored-secret indicator confirms configuration, not a successful connection to the destination service.

Credential replacement

Use the supported administration screen to replace credentials. Existing values are not displayed back in ordinary editors; blank or unchanged fields retain credentials where the screen supports that behavior. Confirm the target company and integration, coordinate the change with the consuming component, then perform a controlled connection check. Replacing credentials is distinct from deleting them or migrating a worker's storage path.

Operational protection

Restrict access to the vault and its encryption-key configuration. Protect backups and retain the keys needed to decrypt their records. An encrypted database backup cannot recover credentials when its corresponding key is lost. Do not place keys or passwords in documentation, logs, screenshots or support exports.

Component compatibility

Confirm the installed worker supports the configured credential path before onboarding or rotating integration credentials. API-side vault support does not automatically upgrade existing background workers or migrate legacy encrypted settings. See component compatibility.

IMS Global Backup & Restore and Secret Vault Encryption-Key-Loss Recovery are planned projects; they are not available recovery workflows in this release. Continue using approved database backup and recovery procedures with protected key material.
