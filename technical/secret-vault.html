Secret Vault

How IMS keeps sensitive database and integration credentials behind the server-side API boundary and exposes only the runtime values needed by authorized components.

Purpose

IMS uses a central protected secret store for credentials that should not be distributed as reusable plaintext application configuration. Access to those values is mediated by IMS.Api and tied to the requesting user/session, workstation, company/module/resource and intended secret.

Company database passwords

The IMS Global Companies screen can register/change a company database password, but an existing saved password is not displayed back in the form. During new database provisioning, IMS Global uses the password supplied for the new database and, after successful creation/validation, stores the secret through IMS.Api.

Operational rule

Do not bypass the vaultDocumentation and integrations should use the approved IMS secret flow rather than copying database/service passwords into user guides, scripts or workstation configuration.

Encryption at rest and runtime access

The inspected vault uses AES-GCM with 32-byte keys, a random 12-byte nonce and a 16-byte authentication tag. Authenticated data binds the company, module, resource, secret name and envelope version. This protects stored entries; it does not mean plaintext never reaches an authorized component.

Ordinary status operations report whether a secret exists without returning it. Authorized runtime reads decrypt the required value and record a READ audit; writes encrypt the value and record SET. SMTP, updater, finance, supplier FTP and Shopify token flows include runtime reads. Integration, VCount and Report FTP controllers expose status/set operations at this source pin.

Replacement is not deletion

Integration key updates require a nonblank value. Changing an integration to Auth Type NONE is not a verified vault-delete operation, and copying configuration cannot transfer a resource-bound secret to a new identity. Shopify updates replace each nonblank supplied credential and preserve entries for blank fields; this API does not guarantee credential-value uniqueness across profiles.

Background-service compatibility

Verify the deployed credential pathIntegration and Shopify secret setters write the central vault without mirroring legacy company credential columns. Validate the deployed background-service version's credential access path before moving profiles to vault-backed credentials. A saved profile alone does not prove that a legacy worker can read its credentials. Compatibility across these source versions remains unresolved; no deployed failure or complete migration is established here.

Source verification: IMS.Api main 91759f4, reviewed 9 October 2026 (provisional source baseline; deployment/release equivalence not verified). encryption envelope; read/write auditing; integration secret contract; Shopify status, read and replacement; central vault upsert; SMTP runtime flow; updater runtime flow; finance runtime flow; supplier FTP runtime flow.
