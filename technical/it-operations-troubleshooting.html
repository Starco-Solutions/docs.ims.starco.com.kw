IT Operations & Troubleshooting

Operational checks for IMS access, company routing, database availability, API/bootstrap services, workstations, background integrations and new-company rollout.

Login/access triage

  1. Confirm the workstation is authorized.
  2. Confirm IMS.Api/bootstrap service availability.
  3. Confirm the global user is active and can authenticate.
  4. Confirm the user has active access to the intended company and that a valid default company exists.
  5. Confirm the company and database profile are active and the target PostgreSQL service is reachable.
  6. After entry, verify the user's company-local Group Policy and Store/Supplier/transfer scope.

Cluster observation

Use IMS Global → System → HA Health for primary/standby, streaming, lag and observation time. Refresh an unavailable observation and involve the database administrator if it persists. The screen is read-only and cannot perform failover.

New company rollout checklist

  1. Create the company/profile in IMS Global.
  2. Use Create DB and allow IMS Global to create/initialize the company database.
  3. Grant the intended global users company access and set the required default.
  4. Open the new company in IMS and complete company-local Stores, policies, users' scope and operational configuration.
  5. Validate System Dashboard connectivity and run controlled operational tests before production use.

Integration incidents

For background/interface problems, separate source-data problems from worker, credential and endpoint problems. Identify the installed worker version, running state, company/profile and affected request or order. Check Autos maintenance state and the owning worker logs before considering an approved recovery procedure. Autos 9.2 and Shopify 4.4.0 use separate API service identities and company grants. Check those grants, Autos Enabled and the relevant company/profile settings. A configured secret is not proof of a successful destination connection.

  • Outbound request: compare the same Business Date in Preview Source and Sync Log; inspect HTTP outcome and Autos errors. Later runs revisit unsuccessful keys only within the configured date window. Check recipient-side acceptance before an approved resend when acknowledgement is uncertain.
  • Supplier email: inspect the selected company’s notification activity and recipient settings. The notification checkpoint advances when the required sends succeed. A failed batch can be revisited, so inspect messages already received before arranging an authorized resend.
  • Inventory mismatch: inspect the company/profile, selected physical stock sources, damage and No Integration exclusions, Shopify Handle/barcode mapping and worker log. Missing or nonunique mappings can be skipped while the cycle cursor advances. After correcting a mapping, use the supported refresh controls rather than assuming the next delta will revisit it. Follow the inventory synchronization guide for timestamp windows, cursors and full refresh controls.
  • Order import or fulfillment: inspect the existing IMS transaction and Shopify order/fulfillment state in the correct company before requesting another action. Use Incoming Orders and Fulfillment Requests to follow the supported workflow.
  • Credential change: distinguish protected host service credentials, company grants and per-store Shopify App Tokens. Use service administration and the authorized credential import procedure. The Global Services grant controls do not rotate credentials.
  • Digital receipt: check the existing company receipt job and channel status. Queued, provider-accepted and delivered are different outcomes. Escalate uncertain outcomes before authorizing another send.

Review and redact request responses and diagnostic logs before sharing them externally. Do not use direct database changes as a generic retry mechanism.

Preserve support boundariesCompany provisioning and global security administration belong to IMS Global/IMS.Api. Do not bypass those controls with manual database or global-user changes unless an approved recovery procedure explicitly requires it.
