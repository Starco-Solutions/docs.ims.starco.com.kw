IMS Security Guard & Secure Bootstrap

The protected startup sequence that validates the IMS workstation, authenticates the global user and establishes authorized company context.

Bootstrap sequence

  1. IMS identifies the workstation and sends the workstation identity/fingerprint and client version to IMS.Api.
  2. IMS.Api confirms whether the workstation is authorized.
  3. The user's global Login Name and password are authenticated.
  4. If a password change is required, the user completes it before continuing.
  5. The API returns only the active companies authorized for that identity, including default-company information.
  6. The chosen company is validated and its runtime database profile is supplied for the authorized session.
  7. The IMS client opens the selected company's operational database and applies that company's local permissions.
IMS Global uses the same security boundaryThe administration application first passes workstation validation and user authentication, then opens a separate Global Administrator session through IMS.Api.

Authentication interfaces and version gates

IMS Security Guard & Secure Bootstrap is the umbrella for workstation registration/authorization, version checks, global login, password-change enforcement and credential bootstrap. It is separate from the external Business API. These internal routes use the application's bootstrap/session contracts, not a partner API key.

PurposeExact route (all POST)
Register/check Client workstation/api/v1/bootstrap/workstation
Client global login/api/v1/bootstrap/login
Authorized user verification/api/v1/bootstrap/verify-user
Client password change/api/v1/bootstrap/change-password
Selected company bootstrap/api/v1/bootstrap/company
Global workstation/login/password change/api/v1/global-admin/bootstrap/workstation, /api/v1/global-admin/bootstrap/login, /api/v1/global-admin/bootstrap/change-password
Global Administrator session and validation/api/v1/global-admin/session, /api/v1/global-admin/validate

The API applies the configured minimum Client version (9.4.6 by default) and a separate minimum Global version of 1.7.0. An unsupported version receives HTTP 426; update the correct application before retrying. Global does not use the Client version gate. Company bootstrap consumes a short-lived token bound to the workstation and authorized company, then returns that company's runtime profile and a session token. An expired or used bootstrap token requires a fresh sign-in, not repeated replay of the same request.

Administrator checks and safe recovery

  • Workstation not authorized: review the registered machine and fingerprint in IMS Global → Workstations; an administrator approves or blocks the device. Registration does not itself establish approval.
  • Password change required: complete the application prompt and sign in again before selecting a company.
  • Company unavailable: check active company/database profile and the user's company assignment. Company access does not grant company-local operational permissions.
  • Login temporarily blocked: wait for the indicated retry interval; do not repeatedly submit credentials.
  • Company secret or database unavailable: ask the administrator to check the database profile, vault configuration and company connection. Do not copy credentials from another company or bypass bootstrap.

Global Administrator sessions authorize administrative work, while employee sessions authorize their selected company context. Autos and Shopify use independent service identities and company grants; they do not run under an employee's sign-in. Protect runtime credentials, tokens and logs on every authorized machine.
