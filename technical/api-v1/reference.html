IMS API 1.1.0.0 • Business API v1

Endpoint Reference

All ordinary Business API v1 resources, query parameters and response-row fields.

All routes below use GET and require the company assignment and named scope. See Requests & Responses for envelopes, required date pairs, paging and types. ? means nullable; decimal values are JSON numbers and long is a 64-bit integer. Preserve document-number precision.

Partner-only access has a separate Partner Data catalog and Stock Delta contract. Ordinary resources can expose business costs and are not restricted by Partner Data policies.

customers

GET /api/v1/companies/{companyId}/customers

Required scope: customers.read, with an active company assignment. Intended for approved monthly, read-only full-catalog exports. Monthly is an integration cadence, not a server scheduler or enforced once-monthly limit.

Query parameters

FieldType / default
pageint, default 1; minimum 1
pageSizeint, default 200; range 1–1000

Only pagination is supported. There are no customer date filters, Delta cursor, push updates or write operations. Invalid pagination returns HTTP 400.

Response row

Exactly twelve fields; ? marks fields that may be JSON null.

FieldType
idlong (int64)
firstNamestring
lastNamestring?
genderstring?
dateOfBirthdate? (yyyy-MM-dd)
phonestring
emailstring?
nationalitystring?
citystring?
starRewardsRegisteredbool
customerCategorystring?
discountPercentint (int32)?

The paged envelope contains companyId, companyCode, companyName, page, pageSize, count, totalCount, totalPages and data. Results are ordered by customer ID.

id is the loyalty customer identifier, not the ERP customer ID. Read Customer identity and enrichment before joining records or interpreting nullable discounts. Count and page rows share a repeatable-read transaction for each request; separate page requests do not share an export-wide snapshot.

Download every page successfully before reconciling your mirror. Do not infer deletions from a failed or incomplete export. See Customers examples.
