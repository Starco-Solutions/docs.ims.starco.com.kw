IMS API 1.1.0.0 • Business API v1

Requests & Responses

Common conventions used for ordinary Business API v1 resources. Partner Data uses the separate envelopes and cursor rules in its guide.

Route pattern

GET /api/v1/companies/{companyId}/resource

companyId must be in the range 1–32767 and assigned to the API client.

Date format

Date parameters use ISO format yyyy-MM-dd, for example 2026-09-30. For date-based transaction/history resources, both fromDate and toDate are required and toDate cannot be earlier than fromDate.

Pagination

Paged endpoints accept page and pageSize. Defaults are page=1 and pageSize=200. page must be at least 1 and pageSize must be 1–1000.

FieldMeaning
pageCurrent 1-based page number.
pageSizeRequested rows per page.
countRows returned in this page.
totalCountTotal rows matching the request.
totalPagesTotal page count for the current page size.
dataResponse rows.

Null and decimal values

Nullable response fields may be JSON null. Nonnullable database-reader mappings can instead produce empty string, 0 or false for database null; follow the endpoint DTO and mapping. Financial, quantity and price fields are JSON numbers and may contain decimal precision appropriate to the underlying business value.

Filtering

Filters are supplied as query-string parameters. Omitted optional filters do not restrict the result. Multiple supplied filters are combined to narrow the result.

Large extracts

For date-based resources, use bounded date ranges. Page through results sequentially. Customers supports only full-catalog pagination, without date filters; its per-request count and rows share a transaction, but pages do not share an export-wide snapshot. Do not request the same large page repeatedly. Respect the client rate limits returned by the service.

Response envelopes

Ordinary successful resource envelopes include companyId, companyCode, companyName, count and data. Stores is unpaged and does not add the paging totals. Other resources add the paging fields above. Required-date resources echo fromDate/toDate; relationship responses also include promotionId or couponEventId.

Illustrative empty items response (fictional company; not a live API result):

{
  "companyId": 1,
  "companyCode": "EXAMPLE",
  "companyName": "Example Company",
  "page": 1,
  "pageSize": 200,
  "count": 0,
  "totalCount": 0,
  "totalPages": 0,
  "data": []
}

totalPages is zero for no matching rows; otherwise it is the ceiling of totalCount / pageSize. Counting and page retrieval are separate database queries using offset/limit. Concurrent changes between page requests can affect export counts and membership. Customers count and page rows share one repeatable-read transaction within each request. Ordinary offset pages have no cross-request snapshot token. Sequential paging does not guarantee a repeatable snapshot. Partner Stock Delta instead has the documented continuation cursor.

Date selection

Sales, purchases, movements, transfers, adjustments, depreciations, markdowns and promotions require both dates. Transaction date bounds are inclusive. Markdowns and promotions select intervals overlapping the requested range inclusively, including records that began earlier. Coupon expiryFrom and expiryTo are individually optional; when both are supplied the end must not precede the start. No maximum date span is imposed by the shared date validator.

Types and filtering

JSON property names use camelCase. DateOnly fields are date strings; TimeOnly fields are time strings; DateTime fields are date-time strings. Do not assume ordinary transaction timestamps are UTC. Partner Delta requires offset timestamps and normalizes them to UTC. Nullability is listed for every field in the endpoint reference.

String equality filters are trimmed exact matches. Supplier search is a case-insensitive substring match of the English or Arabic name, with SQL wildcard characters retaining their wildcard meaning. Supplied boolean filters include false; omission leaves the result unrestricted. nonZeroOnly=true includes positive and negative stock, while false or omission does not filter balances. hasSpecialPrice=true includes non-null special prices, including zero; false selects null.

Accepted filter values

  • Sales transactionType: 51, 52, 53, 54.
  • Purchases transactionType: 1 or 2; documentState: 0–3.
  • Movements transactionType: 1, 2, 51, 52, 53, 54, 81.
  • movementType: SALE, SALE_RETURN, PURCHASE, PURCHASE_RETURN, TRANSFER_OUT, TRANSFER_IN, STOCK_ADJUSTMENT, STOCK_DEPRECIATION.
  • promotionType: BUY_GET, BUNDLE, DISCOUNT, INVOICE_DISCOUNT, SPECIAL_PRICE, STEP_DISCOUNT, STEP_BUY_GET, CASH_BACK.

Movement and promotion type text is trimmed and case-normalized. Promotion and coupon-event path IDs must be positive. Their relation endpoints return empty pages when no related rows match; an empty page does not establish whether the parent exists.

Result ordering

Stable order keys: stores storeId; items itemId; customers id; inventory storeId,itemId; suppliers supplierId; purchases purchaseDate,purchaseCenterId,transactionType,purchaseNo,lineNo; sales saleDate,saleTimestamp,storeId,transactionType,invoiceNo,lineNo; transfers transferDate,transferTime,fromStoreId,transferNo,lineNo; adjustments adjustmentDate,adjustmentTimestamp,storeId,adjustmentNo,lineNo; depreciation depreciationDate,depreciationTimestamp,storeId,depreciationNo,lineNo; movements movementDate,movementTime,storeId,documentCenterId,documentNo,lineNo,movementType; markdowns startDate,markdownId,itemId; promotions startDate,promotionId; coupon events expiryDate descending,couponEventId descending. Relations sort by storeId, clientCategoryId or amountThreshold as applicable; promotion items sort by itemId,rewardItemId nulls last,specialPrice nulls last.
