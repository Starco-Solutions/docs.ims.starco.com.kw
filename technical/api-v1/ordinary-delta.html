Items and Inventory Delta

Keep authorized ordinary item-master and stock-balance mirrors current with incremental snapshots, using the same company contracts and fields as the full exports.

EndpointScopeRow identity / output
/items/changesitems.read(companyId, itemId): ordinary item master fields
/inventory/changesinventory.read(companyId, storeId, itemId): ordinary inventory quantities and valuations

Use the same authorized key, company and ordinary contract as the corresponding full endpoint. These operations do not use the Partner Data availability policy. Inventory rows preserve actual on-hand quantities, including zero and negative values, and financial-data permission still applies to costs. Items retain classifications and permitted purchase/cost information. See Items Delta reference and Inventory Delta reference.

Initial full synchronization

  1. Call the applicable changes endpoint without since. Capture its baselineSince and policyVersion before exporting the ordinary full resource.
  2. Read every page of /items?page=1&pageSize=200 or /inventory?page=1&pageSize=200. Do not filter out zero, inactive or damage stock if maintaining a complete authorized inventory mirror. Stage or apply the full export; reconcile removals only once the entire export succeeds.
  3. Poll the same changes endpoint with since set to its saved baselineSince and its saved policyVersion. Omit through and continuation keys on the first poll.
  4. Apply every incremental page as an idempotent upsert. If fullSyncRequired arrives, restart the corresponding full synchronization using the newly supplied baseline and version.

Parameters and cursor rules

  • since and through are ISO offset timestamps. Use Z or a correctly URL-encoded offset; preserve full precision. Both change-time bounds are inclusive.
  • policyVersion is opaque and must be copied exactly from the corresponding endpoint. Each client, company and endpoint has its own synchronization state.
  • The server chooses a safe through on the first poll. Keep since, through and policyVersion unchanged for every continuation. Do not guess or replace through with the current time.
  • afterItemId is the returned item key. Inventory continuation also requires afterStoreId. Supply both inventory keys or neither. Items Delta accepts only the item key.
  • pageSize defaults to 200; accepted range 1–1000. No page number, totalCount, nonZeroOnly or other ordinary resource filter is supported on these Delta routes.

Envelope field dictionary

Fields appear only in the stated envelope shape. All fields are nonnull except the continuation keys; data is an array even for empty results.

FieldType / shapeMeaning
companyIdinteger; both shapesAuthorized company.
fullSyncRequiredboolean; both shapesTrue instructs a full rebuild; false is incremental.
reasonstring; full-sync onlyinitial_sync_required, history_not_available, policy_version_required or policy_or_catalog_changed.
baselineSinceoffset timestamp; full-sync onlyCapture before exporting the full ordinary resource.
policyVersionstring; both shapesOpaque endpoint-, client-, company- and policy-specific synchronization version.
companyCode / currencyCodestrings; incremental onlyCompany code and currency code; no companyName in Delta.
since / throughoffset timestamps; incremental onlyAccepted fixed window bounds.
countinteger; both shapesRows in data; zero for full-sync instruction.
hasMoreboolean; incremental onlyWhether another page is available.
nextAfterItemIdstring or null; incremental onlyLast item key when hasMore; otherwise null.
nextAfterStoreIdinteger or null; incremental onlyLast store key for Inventory Delta when hasMore; null otherwise and always null for Items Delta.
nextSinceoffset timestamp; incremental onlysince while hasMore=true; through on completion.
dataarray; both shapesOrdinary item or inventory rows; empty on full-sync instruction.

Full synchronization and recovery

Initial requests, unavailable historical change coverage, missing policyVersion, and changed policy or authorized catalog membership can return fullSyncRequired=true. The policy can change when catalog members are added, removed or reassigned, when applicable permissions change, or when the inventory store catalog changes. Do not simply replace the policyVersion on an old cursor; rebuild the relevant complete mirror. No removal tombstones are emitted.

If a request or local write fails, retain the last durable cursor and replay. Persist a continuation key only together with the exact window and version and after its rows are durably applied. A completed empty incremental window still advances nextSince. Boundary rows may repeat; upsert rather than accumulate them.

During company maintenance, requests may return 503 with Retry-After. Retry the same request, without advancing the cursor. Maintenance alone does not invalidate policyVersion and does not require a full export. Follow a full-sync instruction if the actual policy or catalog has changed.

What Delta does and does not represent

Items Delta returns current item snapshots for tracked item-master or stock changes. Inventory Delta returns current balances for tracked store/item stock changes and authorized rows affected by tracked item-master changes, such as price changes. This is not a field-by-field change journal or a list of stock movements. Values are current when read and are not frozen historically at through. The safe window selects changes; each page is a separate request.

Some updates outside the supported change-tracked operations, lookup changes, cost-only background changes or direct removals of stock rows may require a deliberate full refresh. Reconcile periodically according to your integration's needs. A full export is paged, not a single frozen cross-request snapshot.

Use inventory movements for transaction flow and timestamp filters for recorded sales, purchases and movement events; these are distinct from Delta snapshots.
