System Dashboard & Observability

Operational visibility into IMS application versions, company database identity and Global HA observations, latency, workstations, sessions and transaction timing.

IMS Client System Dashboard

The System Dashboard shows application/loader versions, company database/server/time zone, connection statistics, workstation information, Access Log entries and grouped PostgreSQL database sessions. Use it to check the current company and workstation context. High Availability monitoring belongs to IMS Global → System → HA Health.

Transaction performance

The Performance Monitor summarizes captured transaction timing by Store and PC, with optional transaction-type grouping. It shows Min, Max and Average timing. Average duration is classified Good up to 1,000 ms, Fair up to 2,000 ms, Slow up to 4,000 ms and Critical above 4,000 ms. Review the selected date range and filters before comparing results.

Telemetry controlTransaction timing is recorded where Debugging Mode is enabled for the relevant Store under Manage → Stores. It is not a complete record of every Store/date.

Cluster observation

IMS Global HA Health reads registration, streaming and replication lag through the authorized API service using repmgr. Refresh retrieves a new observation; its observation time is displayed locally. A Healthy result requires an observed primary and all expected standbys streaming; it does not imply a measured zero lag. Degraded and unavailable observations require administrator investigation. This is read-only monitoring, not failover control.

Company and worker activity

Use Tools → Autos for company activity logs and filters, alongside the Autos service's Windows Event Log for service-level startup or scheduling issues. Integration Center records integration activity, and Shopify provides company/profile worker logs. A queued receipt, accepted delivery request and confirmed delivery are different states: inspect the existing job and channel result before repeating an action.

Start with company/database identity and connection statistics, then inspect workstation activity, database sessions and available timing records. Review cluster state separately in Global and the relevant worker's activity for external processing. Protect diagnostic exports before sharing.
