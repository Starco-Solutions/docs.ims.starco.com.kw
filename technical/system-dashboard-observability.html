System Dashboard & Observability

Operational visibility into IMS application versions, database/HA state, latency, workstations, sessions and transaction timing.

System Dashboard

The IMS System Dashboard brings application/version state, active company database/server/time zone, HA cluster state, connection latency, workstation activity, Access Log information and PostgreSQL session grouping into one administrative view.

Transaction performance

The Performance Monitor summarizes captured transaction timing by Store and PC, with optional transaction-type grouping. It shows Min, Max and Average timing and classifies health as Good, Fair, Slow or Critical.

Telemetry controlTransaction timing is diagnostic telemetry. It is recorded only where Debugging Mode is enabled for the relevant Store under Manage → Stores; it should not be assumed to exist for every Store/date.

Use in troubleshooting

Start with current database/server identity and connection latency, then check HA state, workstation activity, live sessions and—where debugging telemetry exists—transaction timing. This separates network/session issues from transaction-specific performance problems.

Background-worker evidence

Use the dashboard alongside the owning worker's records: IMS Autos Windows Event Log for maintenance and pre-request failures; Integration Center Sync Log for logged request attempts and HTTP-level results; and Shopify worker logs, product counts and profile inventory watermark for its cycle and mapping outcomes.

The dashboard is not evidence that every background task or external business outcome is healthy. Missing request logs, advancing inventory watermarks and success messages each have limits described in the owning component pages. Local worker logs do not establish centralized alerting or retention. Review and redact diagnostic data before external sharing.
