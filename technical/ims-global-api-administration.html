IMS Global API Administration

Configure and supervise External Business API access as a Global Administrator.

This guide applies to IMS Global 1.6.0.0 and IMS API 1.1.0.0. Confirm the installed software and company database contracts before granting access. Integration developers should use the Business API v1 developer guide for requests, response fields and synchronization.

Administrator accessOpen IMS Global → API Administration with an authorized Global Administrator session. API clients and partner API keys cannot administer their own access.

Dashboard

Review active clients, active keys, today's requests and failures, and average request duration. Use the refresh control to retrieve current figures; investigate individual activity in Request Log and configuration changes in Admin Audit.

Clients

  1. Open Clients. Select a client to view its details, or choose New to create one.
  2. For an existing client, choose Edit. The two buttons change from New and Edit to Save and Cancel while editing.
  3. Enter the required Client Code and Client Name, optional description, Active state, validity dates and Requests per minute/day.
  4. Choose Save to submit the client, or Cancel to discard the editor changes and return to viewing. Company grants, scopes and keys are configured separately.

Companies & Scopes

  1. Select the client in Companies & Scopes.
  2. Choose Edit, select only the permitted companies and required scopes, then choose Save. Use Cancel to leave without applying editor changes.
  3. Verify the saved company assignments and scope selection before handing over a key.

The documented read scopes are stores.read, items.read, sales.read, inventory.read, purchases.read, transfers.read, adjustments.read, promotions.read, partner-data.read and customers.read. Verify that the required scope is registered before granting it. Company assignments and scopes are separate access checks.

Least privilegeGrant customers.read only for an approved customer-data integration. It is independent of partner-data.read and every other read scope. Partner Data policies restrict Partner Data endpoints; they do not restrict general Business API resources. Do not add broad item, inventory or other scopes as a workaround for a partner access problem.

Customer access prerequisites

Customer access needs the Customer Catalog contract in each company database, an active company assignment and an explicit customers.read grant. Confirm the organization's customer-data access and processing approvals before enabling it. Do not treat scope registration as a client grant: verify and explicitly assign the approved client scopes and companies separately.

For new companies, IMS Global → Companies → Create DB applies the consolidated IMS_DB_Create.sql schema. Existing companies require a separately approved migration to the Customer Catalog contract and verification of the API role's read-only view access. The consolidated new-company schema is not an existing-company upgrade procedure. A software update alone does not migrate an existing database. See company provisioning; use the approved administrative migration process rather than running ad hoc production SQL.

Partner Data configuration

  1. Open IMS Global → API Administration → Clients and create or select the API client. Set its validity, active state and request limits.
  2. Under Companies & Scopes, use Edit to assign the company and partner-data.read, then Save.
  3. Open Partner Data, select that client and an allowed company, and choose Edit.
  4. Select the allowed suppliers and eligible physical stock sources. Stores must be active and transaction-enabled, and must not be online or damage stores. All Suppliers and All Stores select the currently listed eligible records; they do not grant a wildcard for future records.
  5. Choose All Supplier Items (ALL) or Selected Items (SELECTED). ALL includes merchandise from allowed suppliers; SELECTED additionally requires active saved item selections.
  6. Set per-item Reduce By Qty (reduce_by_qty) where needed, including in ALL mode. Reductions are nonnegative and accept up to three decimal places. Set the optional maximum discount percentage.
  7. Enable the policy and Save. An active policy requires a supplier and stock source; SELECTED also requires an active item. Generate or rotate the key under API Keys and transfer it securely to the integration owner.

Only authorized Global administration can change policies. Partner keys cannot change suppliers, stores, item selections, reductions or discount ceilings. Changes take effect on subsequent requests and can require a full synchronization. Review Request Log and Admin Audit for activity. Key rotation immediately revokes the previous key.

Review the policy's effect

Production-like performance acceptance is required for large ALL-mode catalogs because eligibility checks examine catalog membership on each Delta request.

All Suppliers and All Stores select the eligible records currently listed. Review and save the policy again when additional suppliers or stores should be allowed. Eligible stock sources are active, transaction-enabled physical stores, excluding online and damage stores.

ALL uses merchandise from the allowed suppliers; SELECTED additionally requires active saved item selections. Reduce By Qty is deducted once from the total across eligible selected stores, then availability is floored at zero. A discount strictly above the optional ceiling makes availability zero; an equal discount is allowed. An otherwise eligible item remains in the catalog with its actual prices and discount.

Coordinate policy changes with the integration owner: changes can require a full catalog synchronization. The consumer's Partner Data & Stock Delta guide explains the synchronization contract.

API Keys

  • Generate: select the client, enter a Key Name and optional expiry, then generate the key. Transfer the complete key securely to the authorized integration owner when it is displayed.
  • Rotate: select an active key and confirm rotation. The previous key is revoked immediately; coordinate the integration's switch to the replacement. The new key name and optional expiry are taken from the form.
  • Revoke: select the key and confirm revocation when its access should end.

The complete generated or rotated key is displayed once and cannot be recovered from the existing-key list. Do not put keys in documentation, tickets or request examples. Review the client and key validity as well as company and scope grants when investigating access.

Request Log

Filter API activity by client, company and HTTP status, and choose the result limit. Entries show endpoint, HTTP status, duration, rows returned, remote IP and controlled error code. Times are displayed in local workstation time. Use failures and request volume to investigate access, request limits or unavailable company contracts with the integration owner.

Admin Audit

Filter API administration actions by action and result limit. Choose All to include Partner Data saves. Review client and access changes, Partner Data policy changes and key generation, rotation and revocation. Times are displayed in local workstation time. Check this history alongside Request Log when reviewing who changed access and the resulting client activity.
