Autos and Shopify service administration

Administer IMS Autos 9.2 and Shopify Integration Server 4.4.0 through their separate service identities and company grants. Both use IMS API secure bootstrap; employee job schedules and online merchandise rules remain in the IMS Client.

Two workloads

ComponentRuntime and responsibilityCompany controls
Autos 9.2.NET 10 Windows service: scheduled business jobs, integrations, reports and receipt delivery.Active service identity, company grant and company Autos Enabled are required. Each company has its own worker and time zone.
Shopify 4.4.0.NET 10 Windows desktop application: independent company/profile workers for orders, fulfillment preparation and inventory quantity.Separate Shopify identity and company grants; each active integrated Store also needs its own App Token. Autos Enabled does not control Shopify.

Open the IMS Global main window and choose the Services administration button for company enablement, service/company grants and Generate Recovery Package. Use Tools → IMS Autos for company job schedules and logs, Reporting Scheduler for reports and Manage Profiles for Shopify merchandise and Store mapping.

Authentication, bootstrap and workload credentials

The workers authenticate with protected service credentials, discover authorized companies and receive each company’s database bootstrap from IMS API. Credentials are protected for their intended Windows account with CurrentUser DPAPI and restricted file permissions. A credential file copied to another account is not an enrollment procedure. Do not put bearer tokens, database passwords or Shopify App Tokens into ordinary settings files or support exports.

Autos has separate workload credential requests for Integration Center, V-Count, SMTP, FTP and WhatsApp receipts. Shopify requests each Store’s App Token for its authorized company. These service routes are technical administration interfaces, separate from external partner Business API credentials and contract scopes.

WorkerAuthorization lifecycle
AutosRediscovers companies approximately every 30 seconds and refreshes bootstrap before each company cycle. Failed discovery, expired authorization or removed company access stops new work while active work drains. Each company waits 30 seconds after its cycle before the next cycle.
ShopifyDiscovers companies at application startup. Before admitting an automatic or manual operation, checks or renews company and per-Store authorization. An admitted operation finishes using its snapshot. Restart to discover newly granted companies.

Nonsecret settings

Autos reads appsettings.json beside the executable: ApiBaseUri, absolute CredentialFile, DatabaseSslMode, optional DatabaseRootCertificate and company-specific workload credential references under CredentialsByCompany. Supported database SSL modes are VerifyFull and Disable. The local DatabaseSslMode must match the mode returned by API bootstrap, configured on the API under Autos:Database:SslMode. A supplied root-certificate path must be absolute and exist on the Autos host. With VerifyFull, configure certificate trust for that host and database name. HTTPS API transport and database TLS are separate settings.

Shopify reads shopify-service.json beside the executable, containing an HTTPS origin in apiBaseUrl and an absolute local Windows path in credentialFilePath. Company database connection details, including Disable or VerifyFull SSL mode, come from bootstrap. The API’s ShopifyService:DatabaseSslMode controls that returned mode; with VerifyFull, the desktop account must trust the database certificate. Per-company/profile runtime preferences are kept in the working directory’s config.ini; these do not contain the service credential. Shopify logs identify both company and profile.

Recovery Package installation

Prepare a Windows replacement host with 64-bit Windows PowerShell 5.1 or later and the .NET 10 Windows Desktop Runtime x64. Sign in as the intended Shopify desktop user, with administrator elevation available under that same account. The host needs access to the package’s HTTPS API origin and each authorized company database endpoint. The runtime check can offer installation through WinGet; if WinGet is unavailable, install the Microsoft runtime before generating and using a fresh package.

The generated installer writes Autos settings with DatabaseSslMode=Disable, no root-certificate path and an empty CredentialsByCompany map. Autos accepts company bootstrap only when its local SSL mode matches the API’s Autos database SSL mode. Confirm the approved database connection mode and required workload credential references as part of replacement-host preparation. The installer also writes Shopify’s API origin and protected credential path; Shopify obtains its database SSL mode from the API. These settings are separate from the HTTPS enrollment connection.

  1. In IMS Global, generate the Recovery Package for the intended Autos and Shopify identities. Keep the package private: its enrollment ticket is a credential.
  2. Stop the old host’s workloads before activating the replacement host for the same identities. Verify that active work has finished.
  3. On the replacement Windows computer, sign in as the intended Shopify desktop user. Launch the generated IMS-Services-Recovery-…exe. Its launcher runs the installation script using 64-bit Windows PowerShell and requests administrator approval under that user. Do not run the whole installer as SYSTEM.
  4. The installer checks package hashes and the .NET 10 Desktop Runtime, stages applications and redeems the one-time enrollment ticket. If the ticket has expired or was already redeemed, obtain a fresh package from IMS Global; do not repeatedly reuse it.
  5. The installer provisions Autos credentials under LocalSystem and configures the Autos Windows service to use LocalSystem. It provisions Shopify credentials for the signed-in desktop user, starts IMS Autos and creates an IMS Shopify shortcut. Existing Shopify preferences are preserved when available.
  6. Open Shopify from the shortcut. Verify authorized companies, profile settings, active Stores and Run on startup choices. Check Autos company logs and the applicable job schedules.
  7. Verify business jobs and intended online processing before retiring old-host credentials through the authorized administration process. Enrollment does not itself revoke previous credentials.

The package’s enrollment ticket is valid for 30 minutes and can be redeemed once. Newly enrolled service credentials have a 30-day lifetime. Shorter authorization leases are renewed during worker operation; renewal does not extend the underlying credential’s expiry. Arrange authorized credential renewal before expiry. If installation fails after enrollment, retain the reported phase and have the administrator review installed files, service state and credentials before another attempt; the ticket may already have been consumed.

Receipt delivery dependencies and monitoring

Autos receipt rendering requires Windows and machine-wide Microsoft Edge. The service renders the original receipt to PDF with one main copy and without gift copies. Configure the company’s email or WhatsApp receipt channel and its authorized provider credential; the cashier workflow must record consent and a valid recipient before delivery.

Review company job logs and the Windows Event Log. A sent receipt means provider acceptance, not confirmed delivery. For an outcome-unknown or interrupted send, inspect the existing request and provider evidence before an authorized resend. Do not reset the queue or create duplicate requests to test connectivity. See receipt result meanings.

Operational checks

  • Confirm service identity, company grants and (for Autos) company enablement independently of employee job checkboxes.
  • Confirm each company’s configured time zone, maintenance time, report schedule and external destination configuration.
  • For Shopify, confirm the selected company/profile, Store App Token, Location ID, Local Store, supplier eligibility and exclusions. No Integration Stores are excluded from automatic API processing.
  • For renewal or connectivity errors, inspect the relevant worker and company log, correct authorization or configuration, then retry the supported operation. Do not replace secure bootstrap with embedded database credentials.
  • Stop Shopify through its UI and wait for active work to drain before maintenance. Stopping or disabling Autos also permits active work to drain rather than terminating business work halfway through.
