How to read claims

  • Source-verified: an inspected code path supports the bounded statement, with immutable references in the correction ledger.
  • Reported: existing documented product policy or an owner-reported setup; not automatically runtime proof.
  • Runtime-unverified: deployed versions, configuration, external acceptance, failover, permissions and recovery outcomes have not been exercised.

Open boundaries

Vault-backed credential setters and legacy-reading workers have an unresolved compatibility boundary. Policy synchronization and administrator identity are under separate owner review. Payment-type handler consistency remains an owner decision. Documentation corrections do not implement those application changes. Purchase work on other branches is outside this baseline.

The Business API contract is a source-backed partial reference, not generated OpenAPI. Selected formulas in the packaged Global API-view SQL are verified. Deployed DDL equivalence, data integrity, upstream allocation, promotion units, upgrade paths and the complete field-level contract still require release-owner reconciliation.
