IMS Server Deployment

Set up a fresh IMS Server and its Global administration database with the supported installer, or recover an installation from approved backups. These are product-level steps for implementers, not the settings of any particular company.

Choose the correct installation modeFresh Installation starts a new IMS Global environment. Disaster Recovery reconnects an approved restore. Do not select Fresh against an existing operational database, and do not use DR as a normal software updater.

1. Prepare a new IMS Server

  • Use a supported Windows Server x64 host (Windows Server 2019 or later), with administrator access, adequate resources and a maintenance window.
  • Obtain the complete, approved IMS Server installation package and keep its supplied components together. Start from Setup.exe; do not manually install the packaged database schema or service components.
  • Prepare PostgreSQL 18.3 or a later supported 18.x minor release. The installer validates its supported version; PostgreSQL installation, backup and high availability are the database administrator's responsibilities.
  • Prepare the intended IMS API DNS name, HTTPS port and a trusted matching TLS certificate, plus a dedicated IIS site, application pool and new deployment directory.
  • Prepare the PostgreSQL connection target and a database administrator authorized to complete the installation. Choose database TLS settings according to your organization's approved certificate and network configuration.
  • Ensure the installer can complete Windows/IIS prerequisites and .NET 10 Hosting Bundle checks from the approved package. Restart only if the installer requests it.

Optional PostgreSQL sizing recommendations

In Setup, open PostgreSQL recommendations…. Review workload assumptions, network access and configuration preview; enter the anticipated users, services and reporting load, then select Calculate / reset values and Preview configuration. You may export the recommendation for DBA review. Previewing recommendations does not change the PostgreSQL server.

2. Fresh Installation — step by step

  1. On the prepared server, run Setup.exe as a Windows administrator and select Fresh Installation.
  2. Enter the API DNS host name, select the trusted certificate and supply the requested IIS site, application pool, deployment directory and HTTPS port.
  3. For a first-time system, leave optional Update Server configuration at Skip (normal API installation only); configure updates after the API and administration access are verified.
  4. Review prerequisite prompts and install missing approved Windows/IIS or hosting components. If a restart is required, restart and resume Setup.
  5. Enter the target PostgreSQL host, port, new Global database name, SSL mode and approved PostgreSQL administrator credentials.
  6. Create the initial IMS administrator password and complete the remaining protected credential/recovery prompts shown by Setup. Safeguard the resulting recovery material through your organization's approved secure custody process.
  7. Review the complete deployment summary—database destination, HTTPS address, paths and versions. Confirm Apply this deployment plan? only after the details are correct.
  8. Wait for IMS Global initialization, API installation and HTTPS health verification. Review the installer outcome and retain the supplied installation record.
Do not retry Fresh over a partial installationIf Setup stops after creating an installation resource, retain the logs and have the administrator follow the installer-supported continuation or recovery process. Do not manually delete databases or other IIS resources to force a rerun.

3. Authorize the first administration workstation

Run IMS Global from the intended administration workstation and follow the approved initial workstation-authorization procedure for a new installation. A newly registered workstation is not automatically approved. The initial authorization requires an authorized implementation administrator; this release does not provide a completely self-service first-device approval inside the installer.

Once an authorized Global Administrator workstation is available, subsequent devices can be approved or blocked through IMS Global → System → Workstations. Do not authorize an initial workstation by editing database records.

4. Create the first company and connect IMS Client

  1. Sign in to IMS Global, open Companies and create the intended company and its database profile.
  2. Enter its approved PostgreSQL destination and credentials through the displayed fields, select Create DB, verify the target and complete the authorized prompts. See Create a company database.
  3. Use Users to assign the relevant users to the company. Review each user's company-local Group Policies, Store/Supplier permissions and approved access.
  4. Configure the approved IMS Client to connect to the HTTPS API, authorize its workstation and sign in to the correct company.
  5. Verify essential transactions, reporting and authorized integration services before production use.

5. Administrator credentials and installation protection

Setup distinguishes initial administrator access from the runtime credentials needed by installed IMS components. Supply the requested credentials only through the installer, never through public examples, commands or documentation. Account names and credential requirements are shown by the supported installation wizard. Store installer-issued recovery material securely and follow your organization's credential-rotation policy.

Disaster Recovery — step by step

Confirm recovery isolationRestored company connection profiles may still refer to an earlier database host. Verify that the recovery environment cannot accidentally connect to production before testing or changing restored profiles.
  1. Prepare a replacement Windows host, the complete approved IMS Server package and a trusted HTTPS certificate.
  2. Have the responsible database administrator restore the approved Global and required company database backups to separately verified recovery destinations.
  3. Run Setup.exe and select Disaster Recovery. Complete Windows/IIS prerequisites and provide the recovery database connection when prompted.
  4. Use your organization's approved recovery material and authorized credential prompts to complete the wizard. Do not create new credentials or replace retained ones without understanding the operational consequences.
  5. Review the deployment plan. Use the installer's supported company database check when the target has been independently verified.
  6. After successful API and HTTPS checks, open IMS Global and review each restored company's displayed database host, port, name and SSL mode. Update the profile through the Companies screen when necessary; do not select Create DB for a restored database.
  7. Verify IMS Client login, company permissions, Business API access and the required Autos/Shopify integrations. Return the recovered environment to operation only after authorized acceptance.

Protect required recovery material

Keep the protected recovery information provided during installation in approved organizational custody, independently of the Windows host. During Disaster Recovery, supply only the material requested by the approved installer. If required recovery material is unavailable, stop and consult the authorized implementation administrator; do not experiment with database records or secret files.

Verify the installation and troubleshoot

  • Confirm the API HTTPS endpoint and supported health checks, then sign in to IMS Global from an authorized workstation.
  • Verify Global version information, each company profile and required company access. Fresh creation and DR restoration require different checks.
  • Test IMS Client, applicable reports and business operations. Verify each required integration independently.
  • For interrupted installation, review the phase reported by Setup and use its approved continuation procedure. Do not remove unrelated services, databases, IIS sites, certificates or credential material.
  • Configure and test IMS Update Server separately after the new installation is healthy.
