IMS Global

Central IMS administration for companies and database provisioning, global users/company access, Business API clients/keys, workstations, cross-company tools and system version control.

Administration boundaryIMS Global is a separate administration application. It is not the screen used for normal company transactions or company-local operational permissions.

Access and Security Guard

IMS Global validates the workstation through IMS.Api, authenticates the global user, enforces required password changes and then requests a Global Administrator session. The main window identifies the session as Global Administrator • Security Guard. Each administration module revalidates the session before opening. The session token is held in process memory; local token presence alone does not establish current authorization or expiry. The configured API URL requires HTTPS outside localhost.

Companies and database profiles

The Companies screen stores Company Code, Company Name, Country Code, Calling Code, Currency Code, Time Zone and active status. The database profile contains Description, Host / Server, Port, Database Name, Username, Database Password, SSL Mode and Database Active.

The saved database password is not repopulated into the password field. The screen shows whether a password is already stored; leaving the field blank retains the current secret when editing an existing profile.

Create a company database

Prerequisites: the installation includes the packaged company initialization, Business API, Partner Data and Partner Stock Delta contracts. The PostgreSQL server must already have an isolated ims_api LOGIN role with no elevated privileges or membership in other roles. The company application username must be separate from ims_api and ims_service. Server preparation is separate from company provisioning.

  1. Create or select the company and complete its database profile.
  2. Enter the intended company database password.
  3. Click Create DB.
  4. Confirm the company, Database and target Server.
  5. Enter PostgreSQL administrator credentials when IMS Global prompts for them.
  6. Wait for the Create Company Database operation to complete.

IMS Global creates and initializes the company database. Database creation is an IMS Global administration task, not a manual PostgreSQL setup procedure. After the operation succeeds, the company database password is secured through IMS.Api.

The stages save company metadata, obtain API provisioning details, create the database, apply the packaged schema, configure the company role, initialize data and the API-supplied administrator, then install the Business API, Partner Data and Partner Stock Delta contracts and validate all 24 required API views and read-only API access. The reserved built-in administrator is initialized with Administrators policy 1. The company runtime password is secured through IMS.Api after successful provisioning.

Existing databases need a separate upgrade. Create DB provisions new companies; installing a newer IMS Global does not automatically migrate existing company databases. Apply the approved company migrations and validate API access before enabling the new contracts.

Staged operationThese stages and the final API password save are not one all-or-nothing transaction. Failure can leave an existing or partly initialized database, or an unsaved runtime password. Create DB rejects an existing database. Preserve the operation log and ask an authorized administrator to assess completed stages before retrying; do not assume an error means nothing changed or drop/recreate the database as a routine retry.
Use IMS GlobalDo not create, clone or initialize a company database manually. The supported workflow is IMS Global → Companies → Create DB.

Change a company database login or password

The Company database profile keeps the IMS Client database login separate from the stored password. A saved password is never repopulated into the password field; leave the field blank to keep the current secret.

When an administrator changes the database password for an existing company, IMS Global prompts for a privileged PostgreSQL account. IMS Global uses that temporary privileged session to change the operational IMS Client role, validates the new login and only then asks IMS.Api to secure the updated password in the company profile.

If the database Username is changed, IMS Global again requests a privileged PostgreSQL account. The target login role is created when missing (or reused when it already exists), configured with the permissions required by the IMS Client, validated against the company database and then saved into the company profile.

Privileged PostgreSQL credentials are temporaryThe administrator credentials entered in the prompt are used for the current role/database operation. They are not the company runtime login and are not stored as the company database password.

Changing Username requires a password. Roles are cluster-wide: profiles sharing host, port and role can be affected by the same password change. IMS Global warns and attempts to update matching profiles, but the role change, profile save and API secret updates are separate. Resolve reported partial-save failures before reconnecting affected clients. Newly created roles deny elevated PostgreSQL privileges; reusing a role does not strip its previous privileges or memberships.

API Administration

IMS Global 1.5.0.0 provides the API Administration center for the External Business API v1. It is the supported interface for creating API clients, assigning company access/scopes, controlling request limits and managing API-key lifecycle.

Business API v1 scopes

The current API v1 scope set is stores.read, items.read, sales.read, inventory.read, purchases.read, transfers.read, adjustments.read promotions.read and partner-data.read. Assign only the scopes and companies required by the external integration.

  1. Create or select the API client.
  2. Assign the permitted companies and scopes.
  3. Set client validity and request limits.
  4. Generate an API key and securely transfer the one-time displayed key to the integration owner.
  5. Use Request Log and Admin Audit to verify activity. Rotate/revoke keys when required.

For the consumer-facing contract and request examples, see Business API v1 Developer Guide.

Global Users and company access

The Users screen maintains Login Name, User Name, Email, Cell Phone, Disabled state, password-reset state and Global Administrator status. A user must have at least one company, and exactly one company is marked Default. Company rows separately record whether the user has access and whether that company is the default.

Saving first writes the global identity/company assignment through IMS.Api, then synchronizes local profiles to assigned company databases. These stages are not atomic across companies. A reported synchronization failure can leave the global change saved while company profiles differ. Resolve the reported company failure and verify synchronization before relying on the change.

Each company owns its policy definitions and effective permissions. During user synchronization, existing destination-company memberships are preserved. Additional memberships are copied from the Default company only when both the numeric policy ID and trimmed, case-insensitive name match. Policy 1 is not copied as an ordinary membership, and a missing match does not grant an ordinary user Administrators access. The reserved built-in administrator receives Administrators policy 1.

Review effective permissions in each destination company after synchronization. Matching policy names and IDs do not guarantee that the permissions inside those policies are identical. Company-local Store, Supplier, transfer and transaction rights remain in System → Users Accounts.

Built-in administrator

The reserved built-in administrator cannot be renamed, disabled or stripped of required Global Administrator authority. Existing active-company access is protected; company administration ensures this identity has company access. Use separate named administrator accounts for day-to-day administration and review their access explicitly.

Self-protectionThe account currently running IMS Global cannot remove its own Global Administrator access, disable itself or reset its own password from Global Users.

Workstations

The Workstations administration screen lists registered workstation identity, machine name, authorization state, first/last seen times, fingerprint-change time, hardware fingerprint and notes. Authorized workstations can be blocked and blocked workstations can be approved. The workstation currently running IMS Global cannot block itself.

System Version

System Version maintains the global IMS Assembly Version, Loader Version and Critical-update flag through IMS.Api.

Cross-company setup tools

Clone Policies is intended for reusing selected Group Policy definitions across companies without manually rebuilding every permission set. Clone Suppliers can reuse Supplier/Brand setup and, when selected, related item master data. These are controlled setup tools; they are not a mechanism for cloning an entire company database.
