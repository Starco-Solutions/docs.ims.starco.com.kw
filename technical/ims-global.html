IMS Global

This guide applies to IMS Global 1.7.0.0 and IMS API 1.1.0.0. Confirm the installed software and database migrations for your environment before using these workflows.

Central IMS administration for companies and database provisioning, global users/company access, Business API clients/keys, workstations, cross-company tools and system version control.

Administration boundaryIMS Global is a separate administration application. It is not the screen used for normal company transactions or company-local operational permissions.

Access and Security Guard

Open IMS Global on an approved workstation and sign in as an authorized Global Administrator. Complete any required password-change prompt. IMS Global will display the administration modules permitted to the account. If access fails, review workstation authorization, the configured HTTPS API connection, the user account and required application version.

Main window and menu reference

The main window is titled IMS Global Administration. The Administration area contains six module buttons; the System menu contains workstation, version, HA and exit commands. The Operations Log is a panel in the main window.

Operations Log

The main-window panel displays administration information, success, warning and error messages for the current IMS Global session. Review the relevant operation messages before proceeding after a reported failure. API Request Log and Admin Audit are separate views in API Administration.

System → Exit

Choose System → Exit to close the IMS Global main window.

Companies and database profiles

The Companies screen stores Company Code, Company Name, Country Code, Calling Code, Currency Code, Time Zone and active status. The database profile contains Description, Host / Server, Port, Database Name, Username, Database Password, SSL Mode and Database Active.

The saved database password is not repopulated into the password field. The screen shows whether a password is already stored; leaving the field blank retains the current secret when editing an existing profile.

Create a company database

Prepare a compatible PostgreSQL destination and an authorized database administrator before creating a new company. IMS Global performs supported company-database initialization; you do not run SQL provisioning scripts manually.

  1. Open Companies in IMS Global and create or select the intended company.
  2. Complete its database profile: server, port, database name, username, password and approved SSL setting.
  3. Choose Create DB and verify the company and target server displayed by IMS.
  4. Provide the authorized PostgreSQL administration approval when prompted by IMS Global.
  5. Wait for completion, review the Operations Log and verify the new company's access.
New database onlyCreate DB must not be used to upgrade or restore an existing company database. Existing databases require the supported migration or recovery procedure for their installed IMS version. If an operation is interrupted, preserve the result and ask the implementation administrator to verify the partial state before retrying.

Change a company database login or password

In IMS Global → Companies, select the intended company and review its database destination. The saved password is not displayed back to the user; leave it blank only when the UI indicates that the existing password will be retained.

  1. Enter a new authorized login or password as required by the requested change.
  2. Review the company, database destination and any warning about other affected company connections.
  3. Complete the privileged administrator approval through the IMS Global prompt.
  4. Save and verify the affected company connection. Coordinate credential changes before returning dependent applications and services to operation.

API Administration

Use API Administration to manage External Business API clients, permitted companies and scopes, request limits, Partner Data policies and API keys. The API Administration guide covers the Dashboard, Clients, Companies & Scopes, Partner Data, API Keys, Request Log and Admin Audit workflows for Global Administrators.

Grant only the companies and scopes an integration needs. customers.read is an independent grant: Partner Data access and unrelated read scopes do not authorize customer access. For the consumer-facing contract, see the Business API v1 developer guide.

Global Users and company access

The Users screen maintains login identity, contact information, enabled state, password-change requirements, Global Administrator status, Developer Access and permitted companies. Each active user must have an appropriate company assignment and default company.

  1. Open Users and select or create the named user.
  2. Review the user's active status, company assignments and Default company; Save the authorized changes.
  3. Review the resulting access in each selected company. Company membership does not automatically give the user transaction, reporting, Store or Supplier permissions.
  4. Assign or verify the required company-local permissions through System → Users Accounts in IMS Client.

Built-in administrator

The reserved administrator has protected Global administration rights. Use separate named administrator accounts for ordinary administration and review their company access. IMS prevents certain changes that would remove the active administrator's own access.

Developer Access

Developer Access is an explicitly approved technical-user permission, separate from normal user and Global Administrator permissions.

  1. Select the user in IMS Global → Users and review the assigned companies.
  2. Enable or disable Developer Access and select Save.
  3. When enabling, ask an authorized administrator to complete the Developer Access Approval prompt. Canceling the approval leaves the change unapplied.
  4. Verify the resulting permissions and company access before performing any supported developer operation.

System → Workstations

Open System → Workstations to view registered devices and their authorization status. New devices require explicit approval; registration alone does not grant access.

  1. On an already authorized administration workstation, choose Refresh to load the current devices.
  2. Verify the intended machine using the organization's device inventory and the details displayed in IMS Global.
  3. Select the intended device and choose Approve, or choose Block to revoke access.
  4. Refresh the list, confirm the updated status and retry the relevant application sign-in.

For the first workstation of a newly installed system, see initial authorization requirements.

System → System Version

Open System → System Version to maintain the global IMS Assembly Version, Loader Version and Critical-update flag through IMS.Api.

Published version information and the minimum version required for login are separate controls. Coordinate release files and version metadata with Update Server administration; changing a version record does not install software.

Cross-company setup tools

Clone Policies is intended for reusing selected Group Policy definitions across companies without manually rebuilding every permission set. Clone Suppliers can reuse Supplier/Brand setup and, when selected, related item master data. These are controlled setup tools; they are not a mechanism for cloning an entire company database.

Clone Supplier and Sync Items Master

Use Clone Suppliers for a selected source-to-target setup. Choose different source and target companies, select the supplier, decide whether to include Items Master Data, and confirm the company and supplier names. Supplier and brand setup is copied or matched; the optional item operation also brings the required merchandise dependencies, missing IMS pictures and secondary barcodes. Existing matching items are reused. Newly created items require local pricing and item-state review before selling them.

Open Sync Items Master from Clone Supplier to fill gaps for one supplier across all active companies with active database profiles. At least two are required. This is a shared catalog operation, not a stock-transfer, transaction-copy or price-update operation.

  1. Select the supplier from the combined supplier list and choose a Priority Company. Verify that the intended supplier represents the same business across companies.
  2. Choose Preview. Review the missing merchandise and barcode records and any items that need a different source company.
  3. Review every company in the log. Resolve supplier identity conflicts, product or barcode conflicts, and missing merchandise classifications before proceeding.
  4. Choose Sync and confirm the supplier, priority company and totals. If the catalogs changed since Preview, run Preview again.
  5. Review the per-company results, configure regional prices and item status for newly created items, and run Preview again to confirm the remaining work.
DataSynchronization rule
Source selectionThe selected Priority Company is preferred for item data when available. Preview identifies items whose source is another participating company; review those sources before Sync.
Existing destination itemsPreserve existing item values, including local prices, state and main barcode. Add missing additional barcodes after checking ownership.
New destination itemsBring the selected merchandise and required classifications into the destination. Review regional retail prices and item status locally before use.
IMS themes and picturesIMS item attributes such as Theme are copied for new items. A missing IMS picture for the style/color is copied when inserting a new item; existing destination pictures are preserved. This is not a refresh of pictures for already-existing items.
Shopify-specific dataOnline availability, product mapping, price and synchronization settings require separate configuration in each destination company.
Additional barcodesUse the combined barcode set from the participating companies. A barcode cannot be associated with different items. An existing destination main barcode remains the main barcode.

Hypothetical example: Company Cedar and Company Dune share a supplier. Cedar is the priority company and has item A; Dune has item B. Preview proposes A for Dune and B for Cedar. If Dune also knows an additional barcode for A, it can be added in Cedar. Existing A in Cedar retains its regional price; newly created merchandise in Dune needs local price and status review. Dune's Shopify settings are configured locally. If the same barcode belongs to B in either company, resolve the conflict before syncing.

A stopped synchronization can leave completed companies saved. Correct the reported issue, Preview again and rerun: already-present items and barcodes are recognized. Do not delete valid destination items to force a rerun.

Services: scheduling and company authorization

Open IMS Global → Services, select a company and choose Autos or Shopify. Review the available service identity, enabled state and company grants. Confirm authorized changes and verify the application status in Service Administration.

Generate Recovery Package

IMS Global can generate a supported installer for both Autos and Shopify. Use this workflow when installing or replacing a Services computer; no release scripts or manual service-credential provisioning are required in the public administrator procedure.

  1. Review the intended Autos and Shopify identities and their company grants under Services.
  2. For a replacement, stop or isolate the previous Services host after current work finishes.
  3. Choose Generate Recovery Package, confirm the application/connection details shown by IMS Global and create the installer.
  4. Transfer the installer securely to the intended Windows computer and run it under the authorized Shopify desktop user with Windows administrator approval.
  5. Follow the installer prompts, check Autos service status, open Shopify and verify companies, profiles and scheduled business results.
  6. After verification, complete the authorized old-host retirement process.

Keep the generated package protected and use it within the period indicated by IMS Global. If it expires or installation reports a problem, preserve the message and request a fresh approved package. For prerequisites and verification, see Autos and Shopify installation.

System → HA Health

For IMS installations with supported PostgreSQL high availability configured, open System → HA Health and choose Refresh to review the observed primary, standby nodes, replication state and lag. The screen is read-only; availability information reflects the latest observation, not a failover command.

This screen cannot promote a standby or operate database services. Use the organization's approved PostgreSQL recovery procedures for administration. For workstation and transaction activity, use the IMS Client System Dashboard.
