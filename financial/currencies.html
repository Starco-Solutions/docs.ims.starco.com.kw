Currencies

Currencies maintains the currency master data used throughout IMS and keeps dated Cost Rate and POS Rate history for non-local currencies. One currency is designated as the system's local currency.

Open the screenFinancial → Currencies.

Screen layout

The upper currency grid lists ID, Name, Symbol and whether the currency is Local. Selecting a currency loads its rate history below, ordered from the newest Start Date first.

The toolbar provides New, Edit and Edit Rate.

Currency details

FieldPurpose
NameEnglish currency name.
Ar. NameArabic currency name.
SymbolCurrency sign/code displayed by IMS.
FormatNumeric/currency formatting string used when IMS displays amounts for that currency.
LocalMarks the company's local/base currency.

Local currency

IMS allows only one local currency. When a user tries to mark another currency as Local while one already exists, IMS blocks the save and identifies the current local currency.

When creating a local currency, the currency symbol must also remain unique. The local currency is used elsewhere in IMS to determine the normal local amount format.

ImportantChanging which currency is marked Local affects system-wide financial display/processing assumptions. Treat it as implementation-level master data, not a routine daily change.

Add or edit a currency

  1. Click New to create a currency, or select one and click Edit.
  2. Enter the English Name and Symbol; these are required before Save becomes available.
  3. Enter the Arabic Name and display Format as required.
  4. Select Local only when this is the company's base currency.
  5. Click Save.

New currencies receive the next internal currency ID automatically. After save, IMS reloads the currency list and records the add/update action in the audit log.

Currency rates

For a selected non-local currency, click Edit Rate to maintain:

RatePurpose
Cost RateThe conversion rate IMS stores for costing-related use.
POS RateThe conversion rate IMS stores for Point-of-Sale use.

Both values must be greater than zero. IMS does not open the rate editor for the local currency.

How rate history works

Rates are effective-dated. The grid shows Cost Rate, POS Rate, Start Date and End Date.

  1. If the currency has no previous rate, saving creates a new rate starting on the current server date with no End Date.
  2. When the current rate is replaced on a later date, IMS closes the previous open rate on the day before the new rate begins.
  3. If a rate that already starts today is replaced again the same day, IMS closes the previous record on today's date and creates the new current record with today's Start Date.

This gives IMS a historical sequence of currency rates rather than overwriting the previous values.

Why two rates?The module deliberately stores separate Cost Rate and POS Rate values. Their exact business use is defined by the IMS modules that consume them, so the user guide keeps the two rate roles distinct instead of assuming they must always be identical.
