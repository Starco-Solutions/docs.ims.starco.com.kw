IMS Autos

IMS Autos is the administration screen for the IMS background automation service. It defines the daily maintenance time and selects which scheduled maintenance jobs the server service should run automatically.

IMS Autos 9.2 is a .NET 10 Windows service. One service runs independent company workers, each using its own authorized database, schedules and time zone. The employee screen configures the selected IMS company; service enrollment and company grants are administered separately in service administration.

Open the screenTools → IMS Autos.

Configuration screen and server service

The IMS client screen does not perform the scheduled jobs itself. It saves the automation schedule and enabled options in the IMS database. The IMS Autos Windows service running on the server reads those settings and executes the background work.

This separation allows an administrator to configure automation from the normal IMS client while the server continues to execute the jobs even when that user's workstation is closed.

Run every day at

Select the daily maintenance time, then enable the required jobs. The server worker compares the configured hour and minute with database-local time using the configured time zone. Scheduled report tasks also use the company time zone. Set the schedule for that company’s business day; a second company can run at a different local time on the same service host.

Daily maintenance shiftDuring the scheduled maintenance shift IMS sets the Autos maintenance state so normal transaction processing can be blocked while the selected maintenance jobs are running. This is a cooperative application maintenance state, not a universal database lock. Choose a low-activity time appropriate for the business. The service clears the maintenance state when the shift exits. If a database outage prevents completion, have an administrator review the company activity log and current maintenance status before resuming transactions.

Scheduled daily jobs

Daily stock movement maintenance

The option shown as Save Daily Stock Levels maintains IMS daily stock-movement data rather than simply saving one static quantity snapshot. For each recalculated date, the service rebuilds daily movement from:

SourceMovement treatment
Purchases / Purchase ReturnsPurchases add stock; Purchase Returns subtract it.
Stock TransfersTransfer In adds stock to the destination; Transfer Out subtracts from the source.
Cash / Credit Sales and ReturnsSales subtract inventory quantity; returns add it back.
Stock AdjustmentsUses the signed adjustment quantity.
Stock DepreciationSubtracts depreciated/write-off quantity.

Normally the service recalculates the previous five days plus today: six calendar dates inclusive. If the latest logged movement date is older, it extends the range from the following day. This catch-up does not detect arbitrary gaps before the latest logged date.

Loyalty housekeeping during the daily shift

The server worker also performs required Loyalty/Star Rewards housekeeping as part of the daily automation shift when the corresponding loyalty settings are in use. This includes processing eligible pending reward activity after the configured return period and maintaining applicable loyalty state.

This housekeeping is part of the server-side automation workflow rather than a separate checkbox on the IMS Autos screen.

Nine business processes and receipt delivery

The nine scheduled business processes are loyalty calculations, Sale Seasons, stock recalculation, daily stock movements, Sell Through refresh, Integration Center morning integrations, V-Count, scheduled reports and supplier-order notifications. Receipt delivery is an additional recurring workload. The daily options below do not enable or disable the independent Shopify workers.

Other background work handled by IMS Autos

The Autos service is more than the five daily checkboxes. The current server worker also performs background jobs that have their own schedules or triggers:

Online-order supplier notificationsEvery recurring Autos check looks for online orders created after the last processed order time for each configured Profile/Store, groups their inventory items by Supplier/Brand, and sends the order request to the applicable Supplier Mailing List recipients.
Integration Center MORNING_SHIFTAfter the daily maintenance shift, runs active Integration Center endpoints configured for MORNING_SHIFT and records their result in the Integration Center Sync Log.

Star Rewards automationPerforms recurring Loyalty/Star Rewards maintenance such as applicable expiry and automated loyalty-offer processing.
Reporting SchedulerThe report schedule itself is defined under Tools → Reporting Scheduler. IMS Autos is the server worker that checks those active tasks and executes them at the required time.

Scheduled reports and no-sales periods

Use Reporting Scheduler to choose the Custom Report, daily/weekly/monthly period, recipients and Email/FTP destinations. Autos produces tab-delimited TXT, comma-delimited CSV or XLSX as configured. For a report with no data rows, it sends a no-sales email identifying the reporting period without an empty report attachment; no file is uploaded to FTP for that empty result. Review task results and errors rather than assuming that an absent attachment means a failed report.

Online-order supplier notifications

This workflow is independent from the daily Autos schedule. Each company worker waits 30 seconds after its current cycle finishes before its next cycle. Processing duration is additional, so this is not a guaranteed email delivery interval. Supplier-order checks run when company authorization and the database connection are available.

  1. For each configured online Profile/Store, IMS Autos reads the last processed order date.
  2. It finds newer records already created in IMS Orders.
  3. It loads the inventory-item lines from Order Details and groups them by Supplier + Brand.
  4. Recipients are selected from the Supplier Mailing List: global recipients, supplier-wide/all-brand recipients, and exact supplier/brand recipients.
  5. Autos sends an HTML “new transfer request” email containing Order No., Barcode, Description, SKU/Style, Color, Size and Qty.
  6. After all required sends succeed, Autos advances the last processed order date for that Profile/Store. If sending or saving the result fails, a later cycle can revisit the batch; check the company log and already received messages before arranging an additional resend.
JIT workflow timingFor a JIT online order, the supplier notification happens after the Shopify service has inserted the order into IMS — before the later JIT purchasing transaction created when Incoming Orders is invoiced.

Save the Autos schedule

  1. Select the daily Run every day at time.
  2. Enable the required daily jobs.
  3. Click Save.
  4. IMS stores the schedule and writes a “Modified IMS Autos settings” entry to the activity log.

If all daily-job checkboxes are cleared and the settings are saved, IMS removes the daily Autos schedule record rather than keeping an empty daily shift. Report-task checks and supplier-order notifications run outside that schedule-row condition; the Star Rewards and V-Count paths do not.

Service monitoring and logs

The service records job name, level and message in the current company’s activity log. Use Tools → IMS Autos to inspect company activity and the Windows Event Log for service-level or unavailable-company-log messages. A completed job message describes processing; it does not prove that an external recipient read an email or accepted an integration result.

Company activity log filters

Choose From and To dates and a Level (All by default), then refresh. The initial range is today and the preceding six days. To includes the whole day. The newest 1,000 entries appear first, with timestamp, job name, level and message; timestamps display in the workstation’s local time. Narrow the filters to investigate a job. From must not be later than To.

Receipt email and WhatsApp delivery

After a cashier obtains verbal consent and queues a digital receipt, Autos processes that company’s enabled Email and WhatsApp channels. It verifies the original invoice, consent and recipient, renders one original receipt PDF, and sends that document through the configured channel. Gift receipt copies are not included in this delivery PDF. Email uses the company SMTP configuration; WhatsApp uses the company’s configured provider/template and authorized credential.

ResultOperator meaning
Pending / queuedThe request is waiting for Autos. It has not established provider acceptance.
ProcessingThe worker is preparing or sending the receipt. Do not create another request while it is being checked.
Sent / acceptedThe email server or WhatsApp provider accepted the request. This does not prove customer delivery or reading.
FailedReview the reported reason. Selected temporary rejections and pre-send availability failures can retry automatically, up to three attempts. Configuration, consent and recipient problems require attention.
Outcome unknown / manual reviewA send may have occurred. Check the existing receipt request and provider evidence with an authorized administrator before arranging another send; Autos does not automatically resend an uncertain outcome.

Before taking another action, locate the original transaction in Transactions Expert, confirm its identity and inspect the existing receipt result. If the customer needs an immediate copy while delivery is being checked, follow the supported paper-printing workflow. Do not treat a provider message identifier or sent timestamp as a delivery confirmation.

Administrators registering a new company or replacing the worker host can follow the Autos and Shopify provisioning runbook. Job scheduling is a separate step from service identity registration and company authorization.

Company enablement

The service identity must have a grant for the company, and Autos Enabled must be selected for that company in IMS Global. These are separate controls from the daily job checkboxes. Disabling Autos stops admission of new company work when authorization is refreshed; active work drains rather than being forcibly interrupted. The control does not stop Shopify’s separate workers.
