Operate a campaign from setup to return

  1. Setup: select the correct module and configure dates, values and permitted stores/customers/items. Card profiles and company loyalty settings are distinct from campaign rules.
  2. Eligibility: identify the customer, confirm the store and working date, and review the eligible merchandise or presented card/voucher.
  3. Transaction application: verify the actual POS line prices, receipt total, payment, points or voucher prompt before saving.
  4. Customer result: inspect the saved receipt and the relevant balance, chance or voucher record. A printed document does not create a second entitlement.
  5. Refund/cancellation/reversal: load the original sale and follow that program's return calculation and messages. Review the saved outcome before repeating an action.

Returning purchases with Special Offers

For a supported receipt with one or several Special Offers, the refund is based on the value of the retained basket under the original sale's promotion rules, not simply the displayed price of each returned item. The eligible benefit can move between units when quantities change. A full refund, a partial refund that produces a retained sale and a genuine size exchange have different linked-document outcomes.

Customer requestIMS handling
Return some promotional unitsPreview the repriced retained basket and actual settlement; save linked reversal and retained sale when eligible.
Return all eligible unitsReview the full refund allocation and original payment instruments; an empty replacement sale is not required.
Exchange sizeUse permitted Style/Color and stock checks; link the original, reversal and replacement receipts. A same-value replacement can settle at zero.
Additional payment would be due after repricingRecord a pending physically received return with quarantined stock and supervisor follow-up; do not automatically charge the customer or post a financial refund.

See Special Offers: refund and retained-promotion calculation, POS Preview Settlement workflow and linked receipt and audit enquiry. These Special Offer rules are separate from each loyalty or stored-value program's own eligibility and redemption policy.

Each linked program guide includes an explicitly hypothetical example. Permissions remain those of the existing maintenance screens, Sales Transactions and enquiry reports. Employees use these guides; external developers should use the separate Business API documentation for authorized read access.
