Star Rewards

Operate the IMS loyalty points program: identify customers, understand earnings and tiers, redeem available value and review refunds and expiry.

Company, store and customer setup

System Settings contains Star Rewards activation, calculation after the return period, one-time-code requirement, tier enablement, tier downgrade policy, calculation for nonregistered customers, nonregistered expiry, earning configuration, point value, minimum redemption amount and points expiry days. Store setup separately enables Star Rewards for the store. An authorized administrator maintains these settings; cashiers should use the configured policy and the values displayed by POS.

Identify the customer using country code and mobile number in the transaction's customer-information window. Review registration, profile completion, tier, available wallet and discount before confirming. An existing customer record is not itself proof of Star Rewards enrollment. When calculation for nonregistered customers is enabled, the account can accumulate eligible activity before registration under the separate nonregistered expiry policy. Use Star Rewards History to verify the account.

Eligibility and earning calculation

Earning requires company and store activation and a registered customer, or permission to calculate for nonregistered customers. The sale must be identified to the customer. A discounted receipt records sales history without earning normal purchase points. For an eligible full-price sale, points are the customer's earning multiplier multiplied by the net local amount after voucher-paid value, Star Card-paid merchandise value and rewards redemption, rounded to a whole amount using nearest-even midpoint rounding. The wallet credit is those points multiplied by the configured value per point.

The customer-information flow supplies the tier earning multiplier when tiers apply; the ordinary multiplier is one. The receipt shows the calculated points/value. Do not promise points by multiplying the displayed receipt total without considering discounts, excluded values and redemption.

Tiers and availability

In Loyalty Tiers, use New or Edit to maintain the tier ID, English and Arabic names, Points to Achieve, Earn Multiplier, Max Inactive Days and discount percentage. Required values include the names, achievement threshold, a nonzero multiplier and nonzero inactivity-days value. Keep the intended tier order consistent with IDs and achievement thresholds; the save validation compares adjacent tier values. A tier assigned to a customer cannot be deleted. The inactivity-days field is stored with the tier; use the account's actual displayed tier and the applicable processing rules below when advising a customer.

Tier definitions contain achievement thresholds, earning multipliers and customer discounts. The customer window shows the current tier and progress toward the next tier. Tier recalculation uses total earned points and the configured tier thresholds, not simply the current spendable wallet balance. A tier discount can affect whether a receipt remains eligible for normal full-price earning.

When calculation after the return period is selected, activity is marked Pending until scheduled loyalty processing applies it. The daily job selects transaction dates strictly earlier than the current database date minus the configured company return days; it does not apply them at the start of the boundary day. In that daily processing, No Tier Downgrade preserves a higher existing tier instead of lowering it. Points expiry is a separate deadline: an expiry-days value of zero does not assign a sales-points expiry date; a nonzero value records a date that many days after the transaction. Review Applied/Pending, Available/Redeemed or Canceled, and Expiry Date in the history instead of treating all recorded points as immediately spendable.

Daily processing also handles nonregistered-account expiry. Where the nonregistered expiry period is nonzero and the account is not exempt, the period is counted from its latest loyalty transaction. Once that date plus the period is earlier than the processing date, the account’s points, wallet and total earned are cleared and its loyalty transaction history is removed. Register and verify the customer through the established program process before promising that a provisional balance will remain available.

Redeem with a one-time code

  1. Identify the correct customer and finish the sale lines.
  2. Open rewards redemption and enter the customer's valid, unexpired one-time code when the configured workflow requires it.
  3. IMS checks the matching customer, code, points and wallet amount. The wallet must be positive and meet the configured minimum redemption amount.
  4. Redemption uses available wallet value up to the receipt's net value. For a capped redemption, points are rounded from the redeemed amount using the account's value-per-point ratio.
  5. Review the reduced amount due, complete the payment and save. The saved redemption deducts points and wallet value and records a redemption-history entry.

If the code is invalid or points are insufficient, IMS displays a message. Obtain a valid customer code through the established program process and verify the account; do not substitute another customer's code. Changing the receipt total can require payment details to be entered again.

Refunds, cancellation and reversals

Load the original receipt for a refund. IMS considers its earned points, redeemed points and earlier partial refunds. It can remove earnings attributable to the refund and return previously redeemed value to the wallet. Refund value may be divided between the original monetary payment and Star Rewards wallet; read the displayed split before confirming.

If earned points have already been redeemed and the wallet cannot cover the reversal, IMS asks whether to reduce the refund by the relevant reward value. Declining stops that save. For partial refunds, remaining eligible points can retain the original expiry through a Partial Refund Balance history entry. Authorized Transactions Expert corrections also adjust related rewards history; review the resulting account rather than manually applying a second compensation.

Hypothetical example

Assume company/store activation, immediate earning, a registered customer, multiplier 1 and point value 0.050. A full-price eligible 40.000 purchase with no excluded value earns 40 points worth 2.000. If the minimum redemption is 1.000, a later valid-code redemption can use the available 2.000 against a larger receipt. A refund of the original purchase can require earnings reversal; if that value has already been spent, the cashier must follow the displayed refund adjustment rather than promise a full cash refund plus retained rewards.
